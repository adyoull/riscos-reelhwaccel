Hardware video for RISC OS on the Raspberry Pi: H.264 decoding and encoding on the VideoCore, and HEVC decoding on the Pi 4's HEVC block, for FFmpeg and Reel.

New since v0.2.14: HEVC playback gives its frames back to RISC OS as it goes, so 4K takes far less memory and logical address space. The project is now also built and checked on GitHub with riscos-crossdev.

## Memory and logical address space at 4K

People have been running out of logical address space ("Unable to allocate logical address space") while playing 4K. Every buffer the HEVC block uses is a Physical Memory Pool, reserving logical address space equal to its size:

| | Fixed working buffers | Each frame |
|---|---|---|
| 4K 10-bit | about 50 MB | 16.6 MB |
| 4K 8-bit | about 50 MB | 12.6 MB |
| 1080p | about 12 MB | 3–4 MB |

- **Before:** `hevc_hwdec` made a frame whenever none was free and kept every frame until the decoder closed, up to 32. After a burst (catching up, or after a seek) the peak stayed for the whole film: 14 frames at 4K 10-bit is about 280 MB.
- **Now:** a frame that FFmpeg and the player have let go of goes back to RISC OS once more than two are spare. The `spare_frames` option sets how many (32 keeps them all, as before).
- **hevcdec 0.1.13** adds `hevcdec_frame_free` for programs that use it directly. A frame the block may still be reading as a reference is freed as soon as the block is past it, so nothing waits. `hevcdec_stats` is bigger: rebuild against the new header.
- **Tested:** through FFmpeg every picture is still exact with frames given back as soon as possible (`-spare_frames 0`). Through a player's 12-picture queue, the frames held drop from 15 to 7 once the queue empties.

## Built on GitHub

Every push is built in [riscos-crossdev](https://github.com/adyoull/riscos-crossdev)'s container image, and riscos-crossdev's checks are run on every program and both libraries: static linking, stack probes, no VFPv4-only instructions (so they run on VFPv3 machines), UnixLib consistency, and casts that could load unaligned. A daily workflow offers a pull request when riscos-crossdev has a newer release. Nothing is run on RISC OS there: Pi testing is still done by hand before each release.

## Known

- **The GiveBack test on a Pi** (HEVCTest's ResultG) is still to come. Every picture is checked there with frames given back as hard as possible, pipelined, at 1080p and 4K.
- **Pi 4 only so far.** vcdec and vcenc should work on a Pi 2 and 3 but haven't been tried there.
