Hardware video decoding for RISC OS on the Raspberry Pi: H.264 on the VideoCore and HEVC on the Pi 4's HEVC block, for FFmpeg and Reel.

This is the first release. It is the devkit that riscos-ffmpeg builds FFmpeg and Reel with, and the test programs that check the hardware on a Pi.

| File | What it is |

To watch video with it, use Reel and FFmpeg from [riscos-ffmpeg](https://github.com/adyoull/riscos-ffmpeg): they are built with this devkit.

## What it does on a Raspberry Pi 4

Every picture comes out exactly as FFmpeg's software decoder gives it (for H.264, the VideoCore's chroma can be 1 lower).

| | Pictures a second | ARM time a picture |
|---|---|---|
| H.264 1080p (`h264_vchiq`, zero copy) | 85.7 | 0.13 ms |
| HEVC 1080p 8-bit (`hevc_hwdec`, pipelined) | 353 | 4.0 ms converting (2.0 halved) |
| HEVC 1080p 10-bit | 316 | 4.7 ms to 8-bit |
| HEVC 4K 8-bit | 83 | 16.3 ms, 7.7 ms halved |
| HEVC 4K 10-bit | 79 | 18.0 ms to 8-bit, 10.0 ms halved |

- **`h264_vchiq`:** Baseline, Main and High, 8-bit 4:2:0, up to 1080p. 1080p needs `gpu_mem=128`. Pictures are handed out from the VideoCore's buffers without a copy.
- **`hevc_hwdec`:** HEVC 8-bit and 10-bit 4:2:0 up to 4096x4096, on a Pi 4, 400 or CM4.
  - FFmpeg parses the stream and the block decodes.
  - Frames come out as YUV420P or YUV420P10. They can also be handed out unconverted (`output_hw`), so a player converts each picture once, straight into its video overlay, halving 4K for an HD screen.
  - There's `drop_before` for a player that has fallen behind.
- **Fallback:** both decoders refuse what their hardware can't do with AVERROR(ENOSYS), so a player opens FFmpeg's software decoder instead.

## Known

- Only tested on a Pi 4. vcdec should work on a Pi 2 and 3 but hasn't been tried there.
- Needs RISC OS 5 with the VCHIQ module (in the Pi ROMs) for H.264. On RISC OS before 5.29, contiguous memory that would take the running program's page is refused rather than risked.
