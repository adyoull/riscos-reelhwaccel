Hardware video for RISC OS on the Raspberry Pi: H.264 decoding and encoding on the VideoCore, and HEVC decoding on the Pi 4's HEVC block, for FFmpeg and Reel.

New since v0.2.15: hardware decoders and encoders now give the VideoCore's memory back when a stream ends and when a program exits, and a Pi test shows how many decoders can work at once.

## How many decoders at once (Pi 4, gpu_mem=128)

A decoder takes its share of the VideoCore's memory when its stream starts, so how many fit depends on the picture size. Measured with VCDecTest's Multi:

| Clip | Decoders at once | Result |
|---|---|---|
| 1080p | 1 | Works. |
| 1080p | 2 or more | The second opens, but waits for memory until the first is closed. After 5 s it gives up, and FFmpeg falls back to the ARM. |
| 360p | 2, 3, 4 | All decode together, at about 370 pictures a second in all. |

With six 1080p decoders open, the VideoCore stopped answering. **Programs should keep one 1080p hardware decoder open at a time.** One decoder and one encoder together, as in riscos-ffmpeg's Convert window, are fine.

## The VideoCore's memory given back

- **At the end of a stream:** once the last picture has been taken, vcdec destroys the decoder in the VideoCore, so its memory is free even while the program keeps the codec open. A seek creates it again.
- **When a program exits:** every decoder and encoder still open is closed, including pictures still held. Before, a program that exited without closing left the VideoCore's memory taken until a restart, and every later hardware decode failed. Pi-checked with VCDecTest's Exit: three runs that quit part way, then a whole decode, all worked.
- **Not covered:** a program ended by Escape or a crash, because UnixLib runs no exit handlers then. A program can call `vcdec_close_all()`, `vcenc_close_all()` and `hevcdec_close_all()` from its own signal handler. After an Escape without that, restart before the next hardware decode.
- **Clearer error:** a decoder that gets no memory now fails with "the VideoCore has no memory left for it".

## Also

- **One copy of the VideoCore code:** vcdec and vcenc now share their connection to the VideoCore (`vcdec/vcmmal.c`), instead of each having a copy. Nothing they do has changed: every test's output is identical.
- **Upgrading:** `vcdec_stats` is bigger (`freed_at_end`), so rebuild anything that uses it against the new headers.
